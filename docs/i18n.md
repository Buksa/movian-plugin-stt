# Translating a Movian plugin

How SmartTwitchTV shows its UI in English, Russian, Spanish and Italian, and how to do the
same in your plugin. Checked against Movian `movian6` (`~/movian-public-clean`, 0faa94a0d).

## What Movian gives you, and what it does not

| Need | Movian | Use it? |
|---|---|---|
| Current UI language | `global.i18n.iso639_1`, the first two letters of the chosen catalog: `en`, `ru`, `it`… Spanish is `sp_SP.lang`, so it reports **`sp`**, not `es`. `src/i18n.c:534-553` | Yes, with an alias for `sp` |
| Translate plugin JS strings | Nothing. No `_()`, no module, no way to register a `.lang` file. | Ship your own files |
| `_("text")` in GLW views | Looks up **Movian's own** catalog only. `glw_view_parser.c:567` | Only if your plugin has exactly Movian's languages |
| `/api/translation` | Translator tool. It loads into the global catalog and is wiped on the next language change or restart. A raw POST clears Movian's own translation first. | No |
| Read a file from the plugin folder | `fs.readFileSync(Plugin.path + 'lang/ru.lang')`. Works from a dev folder and from an installed zip (`zip://…`). Other paths are refused ("Access not allowed"). | Yes |
| `plugin.json` title / description | Plain strings, one language. `src/plugins.c:411-442` | Keep English |

## Layout

```
i18n.js          loader + t() + the text ids the views use
lang/ru.lang     one file per language, Movian's .lang format
lang/es.lang
lang/it.lang
```

English has no file: the English text is the key and the fallback.

```
language: Spanish
native: Español
#
# id: is the English text the plugin shows, msg: the translation.

id: Channel: %s
msg: Canal: %s
```

Adding a language = adding `lang/<code>.lang` with every `id:`. No code change.
The file name is the two-letter code Movian reports (`es` via the `sp` alias).

## JS

```js
var t = require('./i18n').t;

page.metadata.title = t('Live streams');
throw new Error(t('Twitch playlist unavailable (HTTP %s).', response.statuscode));
```

`i18n.js` (see the file for the whole thing, ~60 lines):

- reads `global.i18n.iso639_1` on **every call**: it is unset when Movian starts plugins
  (`plugins_init` runs before `i18n_init`), and the user can switch it while the plugin runs;
- maps `sp` to `es`; accepts only `/^[a-z]{2}$/`, so an odd value never reaches a file path;
- loads `lang/<code>.lang` once per language and caches it; a missing file or entry shows English;
- substitutes `%s` through a function, so `$&` or `$'` in a search query stays literal.

Rules:

- **Whole sentences with `%s`, never pieces.** `t('Channel: %s', name)`, not
  `t('Channel') + ': ' + name`. Word order differs between languages.
- **Never call `t()` at module load.** Keep English in tables and translate at use:
  `var sections = {videos: 'Videos'}; … t(sections[kind])`.
- **Do not translate what you store or compare.** Ids, routes, event names, prop names,
  URLs, regexes stay as they are. If a translated label is saved (we save the chosen quality
  label), match on a stable field too (we match on height + fps).
- Log lines stay English.

## Views

Views cannot read the plugin's files, and `_()` only knows Movian's catalog. So JS puts the
view text on the page, and views read it by id:

```js
// i18n.js
var viewKeys = {navSearch: 'Search', loading: 'Loading Twitch…', views: 'views'};
exports.viewText = function() { /* {navSearch: t('Search'), …} */ };

// main.js, wherever a page gets a plugin view
page.metadata.glwview = Plugin.path + 'views/catalog.view';
page.metadata.i18n = i18n.viewText();
```

```
// parens: a macro body ending in a parameter crashes GLW (Buksa/movian#296)
#define L(KEY) {($self.model.metadata.i18n.KEY)}
#define LP(KEY) {($parent.model.metadata.i18n.KEY)}   // inside an item cloner

widget(label, { caption: L(loading); });
widget(label, { caption: LP(channels) + " " + $self.metadata.channels; });
```

- **Wrap the macro body in parentheses.** `#define L(KEY) {$self.model.metadata.i18n.KEY}`
  crashes Movian (SIGSEGV in `glw_view_preproc.c:237`) and `movian-analyze --check`.
- Inside an item `cloner`, `$self` is the item: read the page through `$parent` (`LP`).
- Macros that take a label take the id: `NAV("search", navSearch, …)` with `caption: L(TEXT)`.
- A file pulled in with `#include` sees the includer's macros. Checking it alone with
  `movian-analyze --check` reports "Unknown function L"; check the including view.
- View text follows a language change on the next page open, like the JS text.

## Test

A Node test, no Movian needed (`test/parsers.test.js` has the full version with stubs):

- collect every `t('…')` literal from the JS sources, plus the keys passed through variables
  and every `viewKeys` value;
- for every file in `lang/`, assert each key is present and has the same number of `%s`;
- assert `sp` reads `lang/es.lang`, an unknown language falls back to English, and `$&` stays
  literal.

Do not test "translation differs from English": `Clips` is `Clips` in Spanish, `Offline` is
`Offline` in Italian.

## Checking it in Movian

```sh
mdev run --name i18n -p /path/to/plugin
# pick a language: ru_RU, sp_SP, it_IT … (the file names in Movian's lang/ folder)
printf '{\n\t"language": "sp_SP"\n}\n' > /tmp/mdev/i18n/persistent/settings/i18n
mdev stop --name i18n && mdev run --name i18n -p /path/to/plugin
mdev props --name i18n global/i18n          # iso639_1 = sp
mdev open --name i18n <plugin-route> && mdev shot --name i18n
```

Delete that settings file for English. To test an installed copy, put the zip at
`<persistent>/mrp/installed/<id>@local.zip`. The `@origin` part is required: without it
Movian crashes at start (Buksa/movian#297).

## Checklist

1. `i18n.js` + `lang/<code>.lang`; every user-visible JS literal goes through `t()`.
2. View text by id through `page.metadata.i18n`; macro bodies in parentheses.
3. No `t()` at module load; stored values stay untranslated.
4. Coverage test over every `lang/` file.
5. Run once per language and look at the main pages.
6. Bump `version` in `plugin.json` so installed copies update.
