# Translating a Movian plugin (English / Russian)

How SmartTwitchTV shows its UI in English or Russian, and how to do the same in your
plugin. Checked against Movian `movian6` (`~/movian-public-clean`, 0faa94a0d).

## What Movian gives you, and what it does not

| Need | Movian | Use it? |
|---|---|---|
| Current UI language | `global.i18n.iso639_1` (`en`, `ru`, …). Set from Settings → Languages; English (`none`) maps to `en`. `src/i18n.c:534-553` | Yes |
| Translate plugin JS strings | Nothing. No `_()`, no module, no way to ship a `.lang` file with a plugin. | Ship your own table |
| `_("text")` in GLW views | Looks up **Movian's own** catalog (`lang/*.lang` in the app's data folder). `glw_view_parser.c:567` | Only for words Movian already translates |
| `/api/translation` | Translator tool. It loads a `.lang` into the global catalog and is wiped on the next language change or restart (`set_language` → `nls_clear`). A raw POST clears Movian's own translation first. | No |
| `plugin.json` title / description | Plain strings, one language. `src/plugins.c:411-442` | Keep English |

So a plugin carries its own strings: a small table for JS, and a macro for views.

## JS: `i18n.js`

```js
'use strict';
var prop = require('movian/prop');

var ru = {
    'Live streams': 'Прямые эфиры',
    'Channel: %s': 'Канал: %s'
    // English text is the key, as in Movian's .lang files.
};

function language() {
    // Read on every call: unset when the plugin starts, and the user can switch it while it runs.
    try { return String(prop.global.i18n.iso639_1); } catch (e) { return ''; }
}

exports.t = function(text, arg) {
    var out = language() === 'ru' && ru[text] || text;
    // A function keeps $&, $' in arg literal (search queries, server error text).
    return arg === undefined ? out : out.replace('%s', function() { return arg; });
};
exports.ru = ru; // for the coverage test
```

Use it wherever text reaches the user:

```js
var t = require('./i18n').t;

page.metadata.title = t('Live streams');
throw new Error(t('Twitch playlist unavailable (HTTP %s).', response.statuscode));
popup.notify(t('Channel added to favorites'), 2);
```

Rules:

- **English is the key and the fallback.** Any language other than `ru`, and any key
  missing from the table, shows English.
- **Whole sentences with `%s`, never pieces.** `t('Channel: %s', name)`, not
  `t('Channel') + ': ' + name`. Word order differs between languages.
- **Never call `t()` at module load.** The language is not set yet when Movian starts
  plugins (`plugins_init` runs before `i18n_init`). Keep English keys in tables and
  translate at use: `var sections = {videos: 'Videos'}; … t(sections[kind])`.
- **Do not translate values you store or compare.** Ids, routes, event names, prop names,
  log lines, URLs and regexes stay as they are. If a translated label is saved (we save the
  chosen quality label), make sure lookups also match on a stable field (we match on
  height + fps).
- Log lines (`console.log`/`warn`) stay English.

## Views: the `T()` macro

GLW reads the language directly, so views need no JS help:

```
#define T(EN, RU) {select($core.i18n.iso639_1 == "ru", RU, EN)}

widget(label, { caption: T("Video quality", "Качество видео"); });
widget(label, { caption: T("Channels: ", "Каналы: ") + $self.metadata.channels; });
```

- Put the `#define` at the top of each top-level view. A file pulled in with `#include`
  sees the macro of the view that includes it.
- Macros that take a title take both languages and call `T()` inside, so no macro call
  is passed as a macro argument (a macro inside a macro body works; we did not rely on
  one inside an argument):
  `#define NAV(KEY, EN, RU, ICON, ACTION) { … caption: T(EN, RU); … }`
  and `NAV("search", "Search", "Поиск", …)`.
- Views switch language live. JS text (titles, notices) changes on the next page open.

### Why not `_()` for the few words Movian already has

`_()` translates into all ~20 Movian languages; your plugin has two. A German user would
get `_("Search")` as "Suche" next to your English labels. Some words also mean something
else in Movian ("Channels" are TV channels there). One rule (`T()`) for every string is
simpler. Use `_()` only if your plugin supports exactly the languages Movian has.

## Test: every key has a translation

A Node test, no Movian needed. Stub the Movian modules, then check that each `t('…')`
literal in the sources has a Russian entry:

```js
var i18n = require('../i18n');
['main.js', 'account.js'].forEach(function(file) {
    var source = fs.readFileSync(path.join(__dirname, '..', file), 'utf8');
    (source.match(/\bt\('(?:[^'\\]|\\.)*'/g) || []).forEach(function(call) {
        var key = call.slice(3, -1);
        assert.ok(i18n.ru[key], file + ': no Russian for ' + key);
    });
});
assert.strictEqual(i18n.t('Channel: %s', "$& x"), 'Канал: $& x');
```

Keys passed through a variable (`t(sections[kind])`) are not found by the regex; list
them in the test by hand. See `test/parsers.test.js` for the full version with stubs.

## Checking it in Movian

```sh
mdev run --name i18n -p /path/to/plugin
# Russian: write the language setting, then restart the instance
printf '{\n\t"language": "ru_RU"\n}\n' > /tmp/mdev/i18n/persistent/settings/i18n
mdev stop --name i18n && mdev run --name i18n -p /path/to/plugin
mdev props --name i18n global/i18n          # iso639_1 = ru
mdev open --name i18n <plugin-route> && mdev shot --name i18n
```

Delete that settings file (or set Settings → Languages to English) for English.

## Checklist for a plugin

1. Add `i18n.js`; move every user-visible JS literal to `t()`, with `%s` templates.
2. Add the `T()` macro to each top-level view; convert captions.
3. No `t()` at module load; stored values stay untranslated.
4. Add the coverage test.
5. Run once in each language and look at the main pages.
6. Bump `version` in `plugin.json` so installed copies update.
